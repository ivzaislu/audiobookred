# Контракт модулей источников

Версия архитектурной границы: 0.24.0.

## Назначение

Модуль источника отделяет общую очередь, runtime-настройки и HTTP-маршруты
AudioBookRed от конкретного парсера. Начиная с 0.24.0 через общий контракт
регистрируются RuTracker и Rutor. Rutor создаётся выключенным и включается
администратором после проверки доступности зеркал.

## Состав модуля

`ISourceModule` описывает статические свойства:

- стабильный ключ источника;
- отображаемое имя;
- состояние enabled по умолчанию;
- категории;
- runtime-настройки по умолчанию;
- возможности адаптера.

`ISourceCrawler` описывает управляющие операции:

- bootstrap discovery;
- incremental enqueue;
- queue worker;
- reconcile;
- pause, resume и reset;
- retry;
- status, events, settings, completeness и maintenance.

`SourceRegistry` проверяет при старте:

- корректность ключей;
- отсутствие дубликатов;
- наличие ровно одного crawler для каждого module;
- отсутствие crawler без module.

`ValidateSourceRegistry` принудительно создаёт реестр сразу после
`builder.Build()`. Ошибка регистрации останавливает запуск до открытия
HTTP-порта, а не откладывается до первого запроса к source endpoint.

## HTTP

Общие операции регистрируются один раз через маршруты:

```text
/api/v1/sources/{source}/...
```

Существующие URL RuTracker не меняются, потому что `{source}` принимает
`rutracker`. Специфичные transport- и legacy-маршруты RuTracker пока
остаются отдельными.

Добавлен защищённый endpoint:

```text
GET /api/v1/sources
```

Он возвращает зарегистрированные модули, их категории, defaults и capabilities.

Неизвестный источник получает `404 unknown_source` со списком доступных ключей.

## Runtime-настройки

`SourceSettingsRepository` больше не использует значения RuTracker для любого
переданного ключа. Defaults выбираются из зарегистрированного `ISourceModule`.
При старте строки настроек создаются для всех зарегистрированных модулей через
`ON CONFLICT DO NOTHING`, поэтому пользовательские значения не перезаписываются.

## Rutor

Rutor использует тот же payload `category + page`, но имеет одну логическую
категорию `11` и нулевую нумерацию страниц во внешнем URL. Адаптер преобразует
внутреннюю страницу `1` в `/browse/0/11/0/0`. Magnet и infohash присутствуют
в строке listing, поэтому отдельная topic-очередь для первой версии адаптера
не нужна. Из раздела «Книги» принимаются строки с аудиоформатами или явными
признаками аудиокниги/радиоспектакля.

## Что намеренно не меняется

- таблицы и существующие данные PostgreSQL;
- ключ и поведение `rutracker`;
- cron RuTracker и общий CLI;
- RuTracker topic и magnet pipeline;
- формат существующих ответов RuTracker.

Rutor в 0.24.0 не выполняет detail metadata reparse: соответствующие общие
методы возвращают результат `unsupported`. Это отдельный следующий этап.
